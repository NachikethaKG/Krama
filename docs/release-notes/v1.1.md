# Release `v1.1` (Phase 4 Reliability)

Release: https://github.com/NachikethaKG/Krama/releases/tag/v1.1 · Tag: `v1.1`

Phase 4 Reliability: tutorials stay correct as websites change. Stored workflows are re-checked on a schedule; UI drift is detected and classified; the agent deterministically self-heals locator misses; otherwise the tutorial is marked **OUTDATED** and routed to the in-app Owner Review Queue. Every modification creates a trackable workflow version with a step-by-step diff.

![Krama v1.1: UI drift detection, self-healing, version history, and owner review queue](https://github.com/NachikethaKG/Krama/releases/download/v1.1/krama-v1.1-reliability.gif)

## What's in it

- **Fingerprinted locators & deterministic self-healing (#112):**
  - Record-time fingerprinting (`ActionExecutor`): role, accessible name, bounding box, container hierarchy, form action/inputs, and element `id`/`name`.
  - Cascade ranking (`healer.heal`): candidate similarity scoring (name 0.30, container 0.20, form 0.20, attributes 0.20, position 0.10).
  - Margin rule: heals deterministically onto candidates scoring $\ge 0.75$ with a $\ge 0.15$ lead over second-best.
  - Multi-candidate disambiguation via Gemini within a strict Redis daily quota (5/day) that fails closed.
  - Full post-condition and downstream flow re-verification before persisting heals.
- **Workflow versioning & step-by-step semantic diffs (#108, #112, #114):**
  - `workflow_versions` table and API (`GET /api/v1/workflows/{id}/versions`).
  - Stored `change_summary` (`StepDiff`) tracking field-level changes (`target.selector`, `target.name`, `instruction_text`, `expected_state`).
  - Automatic promotion: deterministic heals publish live as `current`; candidate heals requiring review are stored as `pending_review` until accepted.
- **Scheduled validation & drift classification (#110, #111):**
  - `ScheduledValidator` running arq cron validation passes against stored workflows.
  - Multi-signal drift detection: accessibility-tree diffs, CPU-friendly Pillow visual screenshot comparison, and box shift tracking.
  - Deterministic classification: `ignore` (cosmetic box shift / minor visual change), `heal` (relocated/renamed element), or `outdated` (structural/flow change, missing target, state mismatch).
  - Exponential back-off schedule for blocked checks or expired sessions.
- **Unified tutorial freshness badges (#114):**
  - Standardized freshness taxonomy everywhere tutorials appear: `verified`, `auto-updated`, `outdated`, `not_auto_checked`.
  - Integrated into Tutorial Library cards, Dashboard My Tutorials list, Tutorial Player header, and Public Share header.
- **Version History & Step-by-Step Diff viewer (#114):**
  - Slide-over Version History drawer filtering out unaccepted heals from viewer playback.
  - Wording-only revisions collapsed by default behind an expandable disclosure toggle (`"Wording-only changes (N)"`).
  - Interactive Step-by-Step Diff viewer highlighting modified steps (old selectors in rose strikethrough vs new healed selectors in emerald).
- **Outdated Site Warning Banner (#114):**
  - Prominent alert banner rendered on public share links (`/share/[token]`) when target site has changed since recording.
- **Owner Review Queue & triage actions (#115):**
  - Owner-only in-app review hub at `/dashboard/reviews` (protected by `middleware.ts`).
  - Category filter tabs: `All`, `Outdated`, `Pending Heal`, `Unstable`, `Can't Check: <reason>`.
  - Live dynamic navigation count badge in `AppHeader` and `DashboardNav`.
  - Context-aware triage handlers: `Accept` (promotes version to active), `Reject` (discards candidate heal), `Regenerate` (`POST /api/v1/workflows/{id}/regenerate`), and `Retry AI Fix` (with inline 429 quota notice on daily cap).
