## 1. Gemini API Setup, Quotas, and Structured Output

### Why Separate Developer Keys Are Required
Google Cloud and Gemini API enforce rate limits **per Google Cloud project, not per API key** [verified: https://ai.google.dev/gemini-api/docs/rate-limits#how-rate-limits-work].
- If multiple developers generate keys under the same GCP project, all calls debit from a single shared quota pool.
- One developer running a benchmark or high-concurrency test can exhaust the project's Requests Per Minute (RPM) or daily Requests Per Day (RPD), starving teammates with HTTP 429 (`RESOURCE_EXHAUSTED`).
- **Requirement:** Each developer must create an API key in their own distinct Google AI Studio project via "Create API key in new project" [verified: https://aistudio.google.com/apikey].
- Keys are kept in the repo-root `.env` (`GEMINI_API_KEY=...`) and are git-ignored to prevent credential leaks [verified: `AGENTS.md`].

### Rate Limits by Model (Free Tier)
Limits observed and documented in Google AI Studio [verified: https://ai.dev/rate-limit] and rate limits guide [verified: https://ai.google.dev/gemini-api/docs/rate-limits]:

| Model | RPM (Requests/Min) | TPM (Tokens/Min) | RPD (Requests/Day) | Context Window |
|---|---|---|---|---|
| `gemini-3.8-flash` | 5 | 250,000 | 20 | 1,048,576 tokens |
| `gemini-3.5-flash` | 5 | 250,000 | 20 | 1,048,576 tokens |
| `gemini-2.5-flash` | 5 | 250,000 | 20 | 1,048,576 tokens |

- **Binding Constraint:** The daily budget of **20 requests/day per model** is the tightest constraint [verified: https://ai.dev/rate-limit].
- **Reset Boundary:** Daily quota resets at midnight Pacific Time (PT) [verified: https://ai.google.dev/gemini-api/docs/rate-limits#how-rate-limits-work].
- **Model Fallback Chain:** To maximize resilience against transient `503 UNAVAILABLE` errors and expand daily headroom, calls cascade across `gemini-3.8-flash` → `gemini-3.5-flash` → `gemini-2.5-flash`, giving an aggregate ceiling of 60 requests/day [verified locally: `docs/research/phase-0-vishwas-gemini-structured-output.md`].

### Structured Output Verification Script
We implemented and verified `scripts/research/verify_gemini_quota.py` using `google-genai` SDK v2.28.0 [verified locally]:
- **Schema Enforcement:** Configured with `response_mime_type="application/json"` and `response_json_schema=StepVerification.model_json_schema()`. This avoids the `400 INVALID_ARGUMENT` bug that occurs when passing Pydantic classes with `extra="forbid"` to `response_schema` [verified locally].
- **Clean Environment Handling:** Inspects `os.environ["GEMINI_API_KEY"]` and falls back to `.env` in repo root. Emits a friendly error message if missing without crashing unhandled [verified locally].
- **Quota & Exception Handling:** Explicitly traps `google.genai.errors.APIError` for HTTP 429 quota exhaustion, extracting latency and error details [verified locally].
- **Sample Run Metrics:**
  - Roundtrip latency: ~4,174 ms [verified locally: `docs/research/assets/phase-0-together-gemini-keys/vishwas-result.json`]
  - Token consumption: 568 total tokens (prompt + output + thinking) [verified locally]
  - Validation: 100% valid parsed Pydantic `StepVerification` instance matching expected schema [verified locally]

## 2. Phase 0 Exit Gate: Reliability Criteria and Failure Classification

### Definition of "Reliably" for Phase 0
For the Phase 0 Exit Gate, **reliably** is formally defined as:
> **$\ge 8$ successful passes out of 10 consecutive deterministic test runs (80% pass rate) executed in a single benchmark batch on Nachiketha's laptop** [verified locally: agreed together in #27].

### Deterministic Test Execution Rules
1. **Dynamic LLM Planning:** Every run must be generated dynamically by the LLM planner (`LLMPlanner`), not hardcoded scripts [verified: `docs/phases/phase-0-spike.md`].
2. **Fresh Environment Isolation:** Gitea test target is reset before the batch; each of the 10 runs targets a uniquely generated repository name to avoid collision [verified locally].
3. **Independent Ground-Truth Verification:** Success is evaluated independently by the benchmark harness via Gitea's REST API (verifying repository exists, is non-empty, and has a README) **and** verified by the internal verifier for every step [verified: `docs/architecture.md`]. The agent never grades itself.
4. **Statistical Confidence:** A score of $\ge 8/10$ yields a 95% binomial confidence interval of **0.49–0.94** [verified locally: computed; `phase-0-nachiketha-benchmarking.md`]. This serves as an effective smoke-test gate proving technical feasibility before expanding into Phase 1.

### Failure Classification Taxonomy

To prevent confounding agent reasoning deficiencies with transient cloud API limits, failures are strictly categorized into two buckets:

| Classification | Category | Description & Examples | Impact on $\ge 8/10$ Gate |
|---|---|---|---|
| **Run Failure** | Agent / Logic Error | - **Locator Miss:** Planner attempts action on a non-existent DOM/ARIA element.<br>- **Schema Validation Error:** Model outputs unparseable JSON or violates Pydantic constraints.<br>- **Action Timeout:** Playwright execution hangs or times out on action execution.<br>- **Verification Failure:** Post-action URL/DOM/ARIA state does not match expected state.<br>- **Crash / Unhandled Exception:** Uncaught error in agent state machine. | **Counts as FAIL.** Degrades the pass rate toward the $< 8/10$ failure condition. |
| **Infrastructure Exception** | Transient / Quota | - **HTTP 429 Quota Exhaustion:** Upstream rate limit exceeded across all models in fallback chain.<br>- **HTTP 500/502/503/504:** Upstream Gemini service outages or overload.<br>- **Network Drop:** Transient socket failure reaching Gemini API. | **Excluded & Re-run.** Does not penalize the agent.<br>**Batch Invalidation Rule:** A maximum of **2 exclusions** are allowed per 10-run batch. More than 2 exclusions invalidates the batch. |

## 4. Summary of Recommendations

1. **Per-Developer Cloud Project Keys:** Each engineer must use an isolated GCP project API key in `.env` to prevent cross-developer quota contention [verified: https://ai.google.dev/gemini-api/docs/rate-limits#how-rate-limits-work].
2. **Quota Preservation:** All unit and contract tests in CI must use `FakeProvider`. Live Gemini quotas are reserved exclusively for benchmark harness validation [verified: `docs/development-workflow.md`].
3. **Structured Output Standard:** Use `response_json_schema` with `BaseModel.model_json_schema()`, avoiding `response_schema` due to incompatibility with `extra="forbid"` models [verified locally].
4. **Phase 0 Exit Gate Update:** Formally reflect the 3 reliability rules ($\ge 8/10$ pass rate, independent API check, $\le 2$ infra exclusions) into `docs/phases/phase-0-spike.md` exit criteria.
