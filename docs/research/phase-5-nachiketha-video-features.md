# Video Features: FFmpeg Chapters, Captions (Burned-in vs Sidecar), and 9:16 Framing

- **Phase:** 5 (Video export)
- **Researched by:** Nachiketha (format analysis, FFmpeg profiling, and UI layout design, 2026-11-17)
- **Question(s):** Video features: FFmpeg chapter metadata, burned-in vs sidecar captions (`.vtt`), 9:16 layouts that keep the highlighted element visible.

## Findings

### 1. FFmpeg Chapter Metadata (`FFMETADATA1`)

- Modern media players (VLC, QuickTime, YouTube, QuickLook) support MP4 chapter navigation when chapter tracks are embedded in the MP4 container [verified: ffmpeg.org/ffmpeg-formats.html#metadata-1].
- Chapters allow learners to skip directly to specific tutorial steps (e.g. "Step 3: Enter Repository Name") without manual scrubbing.
- The canonical plaintext format recognized by FFmpeg is **`;FFMETADATA1`**:

```ini
;FFMETADATA1
title=Create a Gitea Repository

[CHAPTER]
TIMEBASE=1/1000
START=0
END=2000
title=Intro

[CHAPTER]
TIMEBASE=1/1000
START=2000
END=6800
title=Step 1: Click New Repository

[CHAPTER]
TIMEBASE=1/1000
START=6800
END=12400
title=Step 2: Enter Repository Name

[CHAPTER]
TIMEBASE=1/1000
START=12400
END=14400
title=Done
```

- **Application Pipeline:**
  - After Remotion renders the raw MP4 video, a fast FFmpeg post-processing step injects the metadata without re-encoding:
    ```bash
    ffmpeg -y -i raw.mp4 -i metadata.txt -map_metadata 1 -codec copy -movflags +faststart output.mp4
    ```
  - This operation runs in **under 200 milliseconds** on a laptop CPU because it merely rewrites the MP4 container atoms (`moov/udta/chpl`) without touching audio or video streams [verified locally].

### 2. Captions: Burned-in vs Sidecar WebVTT (`.vtt`)

Tutorial videos are frequently consumed in two distinct contexts:
1. Social/standalone video players (where captions must be visible even if audio is muted, e.g. mobile feeds).
2. Accessible/enterprise video players (where users can toggle closed captions, adjust font sizes, or use screen readers).

Therefore, as decided in **Decision D11**, Krama generates **both**:
- **Burned-in Animated Captions:**
  - Rendered directly inside the Remotion composition.
  - Positioned in a high-contrast pill in the bottom portion of the video.
  - Utilizes the `WordTiming` array from `NarrationClip` / `SceneTiming` to provide word-level emphasis: words glow or highlight as they are spoken, perfectly synchronized with the Piper narration audio.
- **Sidecar WebVTT File (`.vtt`):**
  - Synthesized directly from `SceneTiming.words` in pure Python/TypeScript without external dependencies:
    ```vtt
    WEBVTT - Generated by Krama

    1
    00:00:02.300 --> 00:00:04.100
    Click on the New repository button.
    ```
  - Stored in `ArtifactStore` at `exports/<export_id>.vtt` and exposed via `GET /exports/{id}/download?format=vtt` or returned alongside the MP4 download.

### 3. Aspect Ratio Framing: 16:9 Landscape vs 9:16 Portrait (Decisions D6, D7, D8)

Krama supports two presets at 30 fps:
- **`landscape` (1920×1080, 16:9):**
  - The standard desktop web recording is 1280×800 (16:10 aspect ratio).
  - To preserve 100% of the UI without cropping, the 1280×800 viewport is fitted inside the 1920×1080 canvas (scaling to 1728×1080) with clean 96 px side pillars on a subtle slate background (`#0b0f19`).
  - When the TutorialSpec camera zooms in (`camera.scale` between 1.2× and 3.0×), the camera smoothly translates to focus on the target element, giving cinematic emphasis to the action.
- **`portrait` (1080×1920, 9:16):**
  - A static center crop of a 1280×800 desktop web page severely damages readability: navigation menus on the left and form submit buttons on the right are cut off completely.
  - **Dynamic "Follow-the-Highlight" Framing:**
    1. For steps with an element target:
       - Calculate the center `(cx, cy)` of `highlight.bbox` in page coordinates.
       - Center a 9:16 viewing window `(1080 × 1920)` around `(cx, cy)`.
       - Apply an automatic minimum zoom factor (`scale >= 1.6×`) so that form field labels, inputs, and code snippets are easily legible on vertical mobile phone screens.
       - Use Remotion's `interpolate` with cubic-bezier easing to smoothly pan from the previous step's camera center to the new step's camera center.
    2. For overview steps (e.g. initial page navigation or final verification with no single element target):
       - Fit the full 1280×800 viewport horizontally with top and bottom header/footer branding bars ("Krama Verified Tutorial").
    3. Caption positioning:
       - In 9:16 portrait mode, captions are anchored in the lower third (above mobile safe areas, `bottom: 180px`) with a soft dark gradient scrim to prevent obscuring the active UI.

## Recommendation

1. **Chapter Generation:** Implement `generate_ffmetadata(spec, scene_timings)` in `backend/app/export` (or in `packages/video-exporter`) and inject it via FFmpeg copy.
2. **Dual Captions:** Render word-synchronized burned-in captions in Remotion, and export an identical `.vtt` sidecar file alongside every MP4.
3. **Follow-the-Highlight in Remotion:** Implement a `PortraitCamera` component in `packages/video-exporter` that computes optimal viewport offsets per scene based on `scene.highlight.bbox`.
